## 2026-10-23 产品范围重新冻结：分类优先

- **核心目标**：照片放入来源文件夹后，自动把照片按主要拍摄主体分到“单人、多人、人物与风景、风景、动物、植物、其他、待确认”，并允许网页人工修正和移动分类副本。
- **辅助目标**：精选功能改名并定位为“辅助推荐”，只提供技术质量、相似照片和模型建议，不承诺理解个人审美，也不作为项目完成或分类准确率的门槛。
- **明确不追求**：不再以“自动挑出最好看照片”、主观审美高一致性或开源模型达到商业闭源视觉模型水平作为验收条件。
- **算力策略**：优先保证分类稳定和可解释；继续保留GPU/NPU设备证据，但不为追求更大模型牺牲低配置可运行性。视觉大模型不可用时，系统必须明确显示待确认或降级，而不是伪装成高置信结果。
- **下一阶段固定顺序**：先修视觉模型冷启动/超时与单张失败隔离；再修“物件/动物/风景主体中仍有人”的独立真人线索；最后用新的未参与调优样本做分类验收。未完成前不新增精选模型、不大规模改UI、不按编号写特判。C12.1/C12.2/C12.0 已完成；C12.3 受当前网络阻塞，C12.4 保持测试版收口。
- **停止条件**：新样本达到预先记录的分类门槛，连续批次无整批中断，失败照片可定位且不会污染其他照片；若达不到，则交付为“可用分类测试版”，明确待确认边界，不无限调参。

### C12执行细则与有限验收
- C12.0为范围调整后的文案任务，合并到C12.1交付：网页按钮改为“辅助推荐”，详情说明仅供参考；不改推荐算法、不把改名当分类优化。
- C12.1先用已有两次超时原始证据区分冷启动加载、推理和服务错误；最多增加一次有日志的小样本诊断。加载与推理有独立状态和有上限等待；单张失败必须显示原因，不能停用后续整批视觉复核。验收包括超时注入测试、服务未开启、模型不存在、资源不足和小批真图运行；用户强制选择不得被静默替换。不能靠无限增加等待或重试过关。
- C12.2人物存在、主体类别和人数分开记录。只计手部不得推断人数；雕像/公仔不计真人；物件/动物/植物主图可以同时有人。检测框不能单独证明真人，只有经过置信度、面积、坐标有效性和重叠去重后的保守人体证据才可辅助判断人数；冲突只做有限复核，仍不确定保留待确认。已有31条纠错是回归集，不作新准确率。
- C12.3自行收集100张新公开原图（7个主要类别各12张，共84张，加16张遮挡、混合主体、雕像/公仔、局部人体等边界图），保留来源与许可。预测前冻结标签与允许的多义分类；禁止用来源标签或文件名代替真值。由助手独立预标的结果只能称辅助参考评测；提供原图核对页，请用户抽看20张和争议图后才形成有限人工验收，不要求用户大量供图。
- 预先设定的工程收口目标（尚未达到）：在标签已确认样本中，自动归类覆盖率不低于85%，已自动归类的正确比例不低于90%，各主要类别正确归类召回不低于80%；待确认和读取失败不得算正确或从总数悄悄删除，争议图单列数量和原因。7类分别报告，避免总分掩盖某一类别崩溃。
- 稳定性以同一冻结样本连续跑3批检验，至少1批关闭分析缓存重新推理，复用样本只验证稳定性，不能扩充准确率样本量。每批明确结束，无整批假完成；报告冷启动耗时、逐张中位/p95、峰值内存显存，不先承诺跨设备相同速度。低配置以明确拒绝/可选轻量路径保护，不冒称已实测其他电脑。
- C12.4以一次新样本基线、最多两轮全局修复和一次最终冻结复测为上限；若看过新集后再调优，该集改称回归集，不再称独立验证。达到门槛且用户抽验接受则冻结分类MVP；否则列出差距，由用户决定接受测试版或另开阶段。本阶段不继续自动换模型或追求零误差。

### 2026-10-24 最终边界补强与停止点

- 对人脸为零或低置信的照片增加有限旋转复核：只尝试 `90°/180°/270°`，结果映射回原图坐标，不进行无限旋转搜索；清晰结果不重复推理，以控制速度。
- 视觉提示明确：口罩、墨镜、帽子或面部遮挡不等于无人；只要头部、躯干或人体姿态可见，就结合人体检测与视觉语义判断。
- 雕像与模糊真人混合场景不再直接累加人脸候选框；雕像信号存在时，优先使用经过置信度、面积和重叠去重的人体框，一人归单人、多人归多人、证据不足归待确认。
- 验证证据：全部 Node 测试 `134/134`、生产构建、模型资源 `21/21`、lint、文件夹分类边界和 `doctor` 均通过。
- **最终停止**：不再继续增加模型、旋转角度或阈值调优。严重模糊、强遮挡和真人/雕像确实不可区分的照片保留“待确认”，这是分类系统的诚实边界；后续只接受真实用户样本或跨设备验收，不再自动扩展开发范围。

## 0. P5 当前冻结范围

## 1. 项目冻结目标

项目最终交付必须同时满足以下目标：

1. 用户打开网页后，可以设置输入目录、输出目录和计算设备。
2. 用户点击 `一键筛选` 后，把照片放入输入目录即可自动分析并复制到七类结果目录。
3. 用户点击 `生成精选候选` 后，对已经分析的照片进行技术质量排序并输出精选副本。
4. CPU、核显、独显和真实 NPU 路径有清晰边界；NPU 必须有照片推理结果和 VitisAI profile 证据，不能只写硬件探测成功。
5. 公开样本评估、稳定性、功耗和真人试用的证据边界清楚；没有证据的指标必须标记为未测、部分完成或外部阻塞。
6. 项目到达最终停止点后，不再新增入口、模型、竞品报告或无限性能试验。

## 2. 固定推进规则

### 2.1 唯一状态源

- 阶段状态以本文件的“当前状态表”和 `LensSort_AI_执行清单.md` 顶部状态为准。
- 每次只允许一个阶段处于“进行中”。
- “工具已完成”不等于“人工审核已完成”；“候选标签”不等于“项目真值”；“测试通过”不等于“性能提升”。
- 每完成一个步骤，必须按固定顺序执行：完成检查 → 生成证据 → 更新状态 → 记录停止点/下一步 → 才能开始下一步骤。
- 如果发现范围变化、依赖变化或验收口径变化，必须先修改本文件并说明原因；没有修改计划前不得边做边改目标。

### 2.2 状态定义

- `已完成`：所有验收条件满足，并存在可定位证据。
- `进行中`：当前唯一正在执行的步骤。
- `待人工操作`：工具和入口已准备好，但需要用户或真人完成操作。
- `外部阻塞`：需要功率计、参与者等项目外条件；不重复无效尝试。
- `已停止`：按照停止条件主动结束，不再继续扩展。
- `未开始`：尚未进入该步骤。

### 2.3 固定证据格式

每个步骤至少记录：目标、输入、执行时间、命令或操作、结果、失败/边界、输出文件、是否满足门槛、下一步。证据统一放在 `artifacts/`，说明文档放在 `docs/`，不得只在对话中口头确认。

### 2.4 Windows 执行纪律

- PowerShell 只执行 PowerShell 命令；`.js/.mjs` 用 Node，`.py` 用 Python。
- 文档和源码修改必须通过 `tools/apply_patch_utf8.py`，先运行 `--check`。
- 不使用 Bash heredoc，不把 `$LASTEXITCODE` 用来判断 PowerShell cmdlet。
- 测试失败、工具失败、业务失败分别记录；失败证据不能当作通过证据。
- 网页服务启动验收使用临时配置和精确进程归属；开机启动不是本项目必需条件，不要求修改用户现有启动项。

## 6. F5.2 人工审核固定口径

- `单人`：主体为一人，且不是明显的群体场景。
- `多人`：主体为两人或以上，且不是以环境为主的合照风景。
- `人物与风景`：人物是重要主体，同时环境/风景也是主要内容。
- `风景`：无明显人物主体，以自然或城市环境为主。
- `其他`：上述类别均不适合，但图片有效。
- `待确认`：图片损坏、语义确实模糊、边界无法可靠判断；不能把所有错误预测都塞入此类。
