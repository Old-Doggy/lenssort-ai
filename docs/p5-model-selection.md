# P5 精选模型与状态一致性方案

> 版本：P5.1｜日期：2026-10-16｜状态：方案已冻结，尚未修改生产代码

## 1. 本轮目标

本轮只解决三个用户可感知问题：

1. 精选候选排序不符合“好照片”直觉；
2. 分类结果错误后，用户不能在网页内修正并同步到输出标签目录；
3. 页面继续显示上一次状态或“未读取”状态，用户无法确认当前磁盘事实。

原图保护不变：输入目录中的原图不删除、不移动、不覆盖。网页中的“移动分类”只移动输出副本；如果输出副本不存在，必须先提示重新筛选或恢复输出，不能偷偷操作输入原图。

## 2. 模型资料核查结论

### 2.1 候选比较范围（最多三种）

| 候选 | 用途 | 可获得资源 | 初步优点 | 初步风险 | 本轮决定 |
|---|---|---|---|---|---|
| LAION aesthetic predictor V1（现有） | 社交图片/美学候选分 | 项目已有权重与推理链路 | 已接入、速度和离线运行边界已知 | 用户实测排序不稳定；不能单独代表审美 | 保留为基线，不单独决定精选 |
| MUSIQ-AVA | 无参考图像质量/整体观感候选分 | Google Research 官方代码与 TensorFlow Hub/检查点入口 | 支持非规则尺寸，适合比较整体照片质量 | TensorFlow/PyTorch 转换和 Windows 部署成本；授权与权重分发需单独核对 | 进入离线对比 |
| MANIQA-KONIQ | 无参考质量排序 | 官方 PyTorch 仓库和公开 checkpoint | 面向真实场景质量评价，局部质量敏感 | 默认偏“质量/失真”而非个人审美；运行依赖较重 | 进入离线对比 |

### 2.2 暂不纳入生产首轮的候选

- TOPIQ：实现可从 IQA-PyTorch 获取，但该工具箱声明的 PolyForm Noncommercial/S-Lab 授权组合需要单独做商业使用审查；本项目当前不把它直接作为可分发生产依赖。
- Q-Align：模型和运行时重量更大，适合研究对比，不适合本轮直接塞入网页主流程；先不下载。
- 经典 NIMA：资料和实现成熟，但模型较旧，作为补充基线即可，不占用本轮三候选名额。

### 2.3 重要边界

- 开源仓库可访问不等于模型权重、训练数据和商业分发授权完全相同；正式交付前必须把代码许可证、权重来源和再分发条件分开记录。
- 公开 benchmark 分数不能直接等于用户相册中的主观“好看”；本项目最终使用“质量模型 + 技术质量 + 主体信号 + 相似场景去重 + 用户反馈”的组合。
- 如果 MUSIQ 或 MANIQA 没有在现有样本上明显优于 LAION，项目不继续无限换模型，保留组合并把精选定位为“精选候选”而不是自动替用户审美决策。

## 3. 固定实施顺序

### P5-1 模型离线对比（先做）

输入：现有 P1 失败样本、已有精选回归样本和少量可公开复用的对比图；不读取或上传用户私人照片。

每个候选最多记录：

- 全部样本分数、排序前后照片清单；
- 明显模糊、严重过曝/欠曝、连拍近重复的相对排序；
- p50/p95 单图耗时、峰值内存、设备路径和失败数；
- 权重大小、下载来源、许可证和本地离线可运行性；
- 与现有 LAION 排序的 Spearman 相关，仅作为排序差异观察，不当作真实准确率。

验收：候选必须能在本机完成受控离线批量推理；至少在“明显技术问题过滤”或“构图/观感候选排序”中的一个维度优于基线，且失败率不能增加。若没有明显优势，停止换模型。

停止点：最多比较 3 个候选、最多 2 轮参数调整；生成模型对比证据后停止，不直接修改生产精选逻辑。

### P5-2 人工改分类闭环

新增网页详情中的“修改分类”操作和二次确认。固定标签：`单人`、`多人`、`人物与风景`、`风景`、`动物`、`其他`、`待确认`。

确认后：

1. 将对应输出副本移动到新标签目录；
2. 保留输入原图不变；
3. 在持久状态写入 `manualCategory`、`manualAction`、时间和目标目录；
4. 页面立即刷新当前卡片和分类计数；
5. 下次重新扫描优先保留人工标签，除非用户再次明确修改。

验收：中文路径、同名文件、目标目录不存在、输出副本缺失、重复点击、服务重启后恢复、原图 SHA-256 不变均有专项验证。

停止点：只实现单张详情内的人工修正闭环，不做批量智能纠错、原图搬运或自动学习用户偏好。

### P5-3 真实重新扫描闭环

增加“重新扫描文件夹”按钮和后端刷新接口。刷新以当前输入/输出目录的磁盘内容为事实，不把旧 `records.json` 直接当成当前照片列表。

刷新时：

1. 重新枚举输入照片；
2. 检查源文件是否仍存在、是否可读；
3. 检查输出副本是否存在、是否为普通文件；
4. 新照片加入待分析列表；
5. 被删除或移动的源照片标记为“源文件已移除”；
6. 被手动删除的输出显示“输出副本已删除，原图保留”；
7. 其他输出缺失显示“输出副本缺失，可重新生成”；
8. 页面使用 `cache: no-store` 和刷新后的时间戳，避免浏览器缓存误导。

不默认清空全部分析缓存：人工分类、删除抑制和失败原因必须保留；只有源文件指纹或分析版本变化时才重新分析。

验收：新文件、源文件删除、输出副本删除、输出副本缺失、重启服务、中文路径和浏览器强制刷新均可被区分显示。

停止点：只实现一个可解释的重新扫描闭环，不做文件系统实时推送、后台常驻服务或自动开机启动。

### P5-4 整合回归与冻结

必须通过：

- 模型对比证据和许可证清单；
- 人工修改标签后输出目录变化；
- 输入原图字节和哈希保持不变；
- 重启后人工修正与删除状态保持；
- 重新扫描发现新增、删除和缺失输出；
- 精选仍能幂等运行且不重复生成副本；
- CPU/核显/独显/NPU 设备选择边界不回归；
- 构建、Node 语法检查、控制 API、浏览器主流程和中文路径回归。

最终停止条件：P5-1 至 P5-4 完成后关闭本轮；如果精选仍不符合个人审美，产品文案固定为“生成精选候选”，后续只允许在取得新的人工偏好样本后另立计划，不再无限调分数。

## 4. 本轮不做的事情

- 不把评分模型改成自动删除；
- 不移动或删除输入原图；
- 不新增开机启动；
- 不为每台电脑硬编码 NPU；
- 不把 CPU 辅助算子写成纯 NPU；
- 不把代理标签或公开 benchmark 写成真实相册准确率；
- 不在没有离线证据前下载更多大模型。
