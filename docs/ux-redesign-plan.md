# LensSort AI 用户体验重构计划

> 版本：UX v1.2
> 日期：2026-10-07
> 范围：只重构用户主路径和信息层级，不新增模型能力
> 当前状态：计划修订完成，暂停执行；等待用户审阅后再推进研究、原型或开发

## 为什么现在做

当前页面已经具备导入、质量分析、模型验证、相似组、推荐解释、反馈和导出，但这些能力同时展开在一页中。用户第一次打开时需要自己判断先做什么、哪些结果已经完成、哪些按钮属于普通整理流程，学习成本高。

本阶段把产品从“功能展示页”收敛为“照片精选工作台”：用户先导入，等待分析完成，再按推荐结果处理照片，最后导出精选清单；模型诊断和详细解释只在需要时出现。

## 设计参考与取舍

以下是参考候选与待验证的设计假设。此前没有保存官方页面、版本或开源界面核验记录，因此不能宣称已完成竞品调研或已验证用户效果。

- Apple Photos、Google Photos 一类产品使用照片网格作为主界面，把搜索、筛选和详情作为辅助层，避免用户先理解算法。
- Lightroom、Aftershoot 一类选片工具强调“推荐候选 + 人工确认”，相似照片组内先给一张主候选，再允许快速换图和保留。
- PhotoPrism、Immich、digiKam 一类本地或自托管相册强调导入状态、隐私边界和可恢复的本地资料库。

LensSort 保留自己的差异点：本地优先、可解释推荐、相似组人工确认和偏好反馈。模型名称、原始 ImageNet 标签、耗时和分数不应成为普通用户必须阅读的主流程。

后续研究限于 2 个商业产品和 2 个开源项目，各核验导入、分析进度、相似组、人工选择、导出五个环节。商业候选为 [Aftershoot](https://aftershoot.com/) 和 [Narrative Select](https://narrative.so/select)；开源候选为 [Immich](https://github.com/immich-app/immich) 和 [PhotoPrism](https://github.com/photoprism/photoprism)。这些链接是研究入口，不是当前结论的证据。

每个对象记录来源链接、访问日期、版本或 commit、实际观察、拟借鉴点、舍弃理由与许可证；网页不可访问则标记未核验，不补写体验。优先参考交互，不搬运品牌素材或未经许可证核对的代码。完成四份观察表后停止研究，不继续增加竞品。

## 目标用户路径

```text
打开页面
  -> 选择照片
  -> 点击“开始整理”（一个入口运行分类与人脸分析）
  -> 等待“正在分析”完成，或选择先手动整理
  -> 看到“建议先看”列表
  -> 接受、跳过或打开详情
  -> 在相似组中确认保留版本
  -> 导出精选清单
```

页面上始终只保留一个最主要的下一步。用户可以随时查看全部照片，但不会被诊断面板和模型参数打断。

## 交互原则

1. **一个主行动**：空状态“选择照片”；导入后“开始整理”；处理中显示进度；完成后“查看建议”。必需分析保持可发现，技术参数折叠。
2. **渐进展示**：普通用户先看到推荐、风险和操作；模型名称、设备、耗时和原始标签进入“技术详情”。
3. **动作靠近对象**：卡片主要动作只有保留、跳过；点击照片查看详情，提供撤销。喜欢/不喜欢放在详情的可选偏好区，避免两套反馈同时抢占注意力。
4. **推荐先给答案**：卡片显示状态与一条短理由；分数和完整解释放入详情。每张照片最多一个主要风险提示，其余展开查看。
5. **相似组先处理选择**：组卡片先显示主候选、组内数量和“换一张”；展开后再看全部成员。
6. **状态用用户语言**：使用“正在分析、需要确认、已保留、已跳过、可导出”等表达，技术状态作为辅助信息。
7. **危险动作有边界**：跳过不删除原图；清除数据和恢复偏好明确写出影响范围；导出说明输出的是清单而不是原图压缩包。
8. **移动端先保证可操作**：主按钮、筛选、卡片动作和详情内容不产生横向滚动，次要信息可以折叠。

## 本阶段任务

### UX-0：计划和基线

- [x] 记录当前页面的问题、目标路径和设计原则。
- [x] 明确参考候选和初步产品取舍（尚非实证调研结论）。
- [x] 定义后续每一项的验收和停止条件。
- [ ] 用户同意下一阶段后，完成四份竞品观察表。
- [ ] 绘制空状态、分析中、选片工作台、相似组比较、导出预览五张低保真图。
- [ ] 用户审阅原型后再开发；研究与原型最多两轮调整，仍有分歧就记录并暂停。

### UX-1：首屏与开始分析入口

- [ ] 空状态只有一个明显主按钮和一句隐私说明。
- [ ] 导入后显示照片数量、缩略图准备状态和唯一主行动。
- [ ] 统一“开始整理”入口保留在主路径；模型名称、原始标签与测速下沉到“分析详情”。
- [ ] 分析中显示进度、当前阶段和可继续等待的状态；分析失败时给出继续使用传统分析的入口。

验收：新用户无需阅读技术说明即可知道下一步；导入后 5 秒内能找到主行动；桌面和窄屏都无横向滚动。

### UX-2：照片总览和筛选

- [ ] 默认展示“建议先看”，而不是把所有指标平铺。
- [ ] 筛选名称改成用户任务语言：建议先看、全部照片、相似组、需要确认、已保留。
- [ ] 排序控件变为真正可用的菜单，至少支持推荐优先、导入顺序和清晰度优先。
- [ ] 质量、曝光、人脸和相似度作为筛选依据或详情信息，不全部成为卡片角标。

验收：用户能回答“哪些照片值得先看”和“为什么需要确认”；卡片在普通屏幕上最多保留 3 个关键信息。

### UX-3：照片卡片和详情

- [ ] 卡片主视觉以照片为主，显示状态与一条理由；数字评分放入详情。
- [ ] 增加卡片内的保留、跳过和详情动作，点击图片仍可打开详情。
- [ ] 详情优先显示大图与保留/跳过；理由按需展开，喜欢/不喜欢放入可选偏好区。
- [ ] 技术推理结果放入可折叠区域，避免模型名和耗时占据首屏。

验收：用户不打开详情也能完成保留或跳过；打开详情后能看懂推荐依据和未知因素。

### UX-4：相似组精选

- [ ] 每组只突出一张当前候选，并显示“推荐保留”或“需要确认”。
- [ ] “换一张”和“保留这张”成为组内第一层动作；“恢复系统推荐”作为次级动作。
- [ ] 组成员默认折叠，展开后支持选为候选、保留、跳过。
- [ ] 明确“跳过照片不会删除原图”。

验收：用户能在不理解 dHash、CLIP 或相似度的情况下完成一组照片的选择。

### UX-5：导出与清理

- [ ] 导出按钮固定在工作台工具区，显示可导出数量。
- [ ] 导出前说明输出内容是精选清单 JSON/CSV；原图仍保存在本地。
- [ ] 清除本次数据和恢复默认偏好放入设置或次级动作区，并保留现有确认与回滚逻辑。

验收：用户能区分导出清单、保留照片和清除本地数据三件事；已有持久化和失败回滚行为不改变。

### UX-6：诊断信息收纳

- [ ] MobileNetV4、Face Detector、Face Landmarker 和 CLIP 验证区归入“技术诊断”。
- [ ] 普通用户主流程不需要操作单图模型按钮。
- [ ] 诊断区保留模型状态、设备、耗时、失败原因和重试能力，方便项目演示和排障。

验收：诊断信息仍可访问，普通整理流程不被诊断区阻断；自动化模型验证证据继续有效。

### UX-7：真人测试与收口

- [ ] 重新执行 R1、R2、R3 真人测试，沿用 `docs/user-testing-t6.7.md` 的记录口径。
- [ ] 每轮只记录真实完成情况、卡点、原话、满意度和可比耗时，不从自动化报告推导用户数据。
- [ ] 只修复会阻塞主路径的发现；最多进行一次有限复测。

## 验证方式

- 每个 UX 任务完成后运行 `npm run build` 和 `npm run lint`。
- 涉及交互的任务使用 Chrome 验证，记录控制台应用错误、横向溢出和刷新恢复。
- 先用公开评测图验证流程，再用真人测试验证理解成本；两类证据分开记录。
- 每次修改只做一个垂直切片，验证通过后再进入下一项。

## 本阶段停止点

**P（现在）：计划保存后立即暂停，等待用户审阅。** 本轮不制作原型、不实施界面、不运行产品测试。此前 UX-1 的代码试改和工程回归只证明部分旧流程可运行，不能证明用户容易理解，也不能替代本计划验收。

**P1（后续）：竞品观察表和五张低保真图完成后暂停供用户审阅。** 原型通过后才进入开发。

**P2（后续）：UX-1 至 UX-6 工程验收通过后停止扩功能，进入 T6.7。** UX-7 即 T6.7，不额外再做三轮；R1 发现问题、R2 验证修复、R3 独立验证，三轮结束统一复盘。最多一次阻塞问题复测；仍失败则记录未完成并停止扩张。

满足以下条件后停止 UX 扩展，进入真人测试和项目交付材料：

- 空状态、导入、分析、推荐、相似组、详情和导出形成一条无需解释模型术语的主路径。
- 普通用户能在照片卡片或相似组内完成保留、跳过和换一张。
- 技术诊断仍可访问，但不抢占主路径。
- 桌面和窄屏无横向溢出，刷新后本地照片和选择仍在。
- Chrome 自动化回归通过后进入真人测试；完成 R1 仅代表发现问题，三轮真实记录与问题处理齐全才完成 UX-7/T6.7。

达到停止点后不再新增模型、标签、模式或复杂推荐参数；后续只根据真人测试修复阻塞问题。

## 界面布局与操作约定（待审阅设计）

- 空状态：短标题、选择照片按钮、格式/本地处理说明；示例需主动打开，不用虚构的接受率或节省时间填充仪表盘。
- 准备状态：照片数量、可选模式、开始整理；追加导入与新建一批明确区分，不能把追加按钮写成重新选择。
- 分析状态：已完成/总数与失败数量，默认不显示模型术语；可停止剩余任务，已完成结果保留，停止后禁止旧任务写入新批次。此行为尚需实现验证。
- 工作台：顶部仅保留模式、添加照片、导出清单；主区显示照片，任务导航为建议先看/全部/相似组/需要确认/已保留；人物、风景等放入次级筛选。
- 建议先看：按现有规则排序的待决照片，不等同已保留或可导出；需要确认来自风险/未知项；已保留只统计明确人工保留。切换筛选不改变选择。
- 相似比较：当前候选与另一张并排大图，窄屏上下排列；用户可直接选图，不必盲目轮换。换候选不自动保留，也不丢弃其他照片。
- 导出预览：明确当前规则可能包含自动合格和人工保留，分别显示数量与照片名单；跳过项排除。第一版仍沿用已验证资格规则，若改成仅导出人工选择须另行审阅规则与测试。
- 失败与撤销：分析失败显示可继续手选与重试；保存失败显示未保存，不伪称刷新后能恢复；撤销保留/跳过可见；清除操作确认范围。
