# 常见问题

## 首次安装窗口报错

在项目目录双击 `运行体检.cmd`，先看第一条标记为 `fail` 的检查

- Node.js 要求 22.12 或更新版本
- npm 必须能正常运行
- 浏览器运行时可以用 `npx playwright install chromium` 修复
- 基础资源可以用 `npm run verify:models` 检查

下载中断时重新运行 `首次安装.cmd` 即可，已经校验的文件会跳过。不要把模型权重复制进 GitHub 或源码目录

## 网页没有自动打开

保留 `启动网页控制.cmd` 的黑色窗口，查看里面打印的本地地址；必要时手动打开 `http://127.0.0.1:4317`

如果端口被占用，先关闭旧的 LensSort 服务窗口。服务只给本机使用，不要暴露到公网

不要直接打开 `index.html`，文件夹选择、进度、大图和安全操作都需要本地服务

## 页面提示本地服务不可用

确认是从包含 `package.json` 的项目根目录启动 `启动网页控制.cmd`。如果先打开了网页，再启动服务，需要刷新网页

## 中文文件夹名称显示异常

停止当前批次，重新点击网页中的 **选择文件夹**，再点击 **刷新当前文件夹**。批次运行时不要修改或粘贴路径，开始前确认页面显示的路径正确

## 照片不见了，或者旧卡片还在

在文件管理器删除来源照片或结果副本后，点击 **刷新当前文件夹**。页面会重新按磁盘中实际存在的文件更新

## 分类结果不准确

打开照片详情，使用 **修改分类**。它只移动分类副本，来源原图保持不变。口罩、雕像、远处小人、模糊、旋转和复杂合照仍可能需要人工确认，证据不足时可以保留在 `待确认`

## 图片解释不可用

基础分类不依赖 Ollama。需要图片解释时，运行 `安装本地视觉模型.cmd`，等待模型下载完成，再重新启动 `启动网页控制.cmd`

可以运行：

```powershell
npm run doctor
ollama list
```

如果 Ollama 已安装但没有运行，LensSort 启动时会尝试启动或复用本地服务；如果服务在 LensSort 启动前就已运行，退出时不会关闭它

## 内存或显存不够

切换到 **基础分析** 或 4B 模型，关闭其他占用显卡的程序后重试。9B 是可选的大模型，需要更多内存和显存。强制使用会跳过自动降级保护，可能运行失败，也不会自动下载未安装的模型

## 页面显示有 NPU 或 GPU，但看不到实际使用

检测到设备不等于照片实际使用了设备。选择设备并完成一批后，打开照片详情里的技术依据；只有存在运行证据时页面才会标记 NPU 已验证。驱动、Windows ML 和硬件 provider 都必须正常

## 如何反馈问题

请提供 Windows 和 Node.js 版本、操作顺序、命令窗口或页面中的第一条错误，以及一张测试照片能否复现。提交 Issue 前请删除个人路径、照片、令牌和模型缓存信息
