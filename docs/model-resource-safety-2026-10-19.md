# 模型选择与资源保护：固定插入阶段 S1–S5

## 范围与停止条件
本阶段只解决用户反馈的内存/显存风险和网页模型选择，不替代 R4 精选修复。完成 S1–S5 后停止扩展候选；不自动下载大模型、不结束用户其他服务、不修改开机启动。

## 固定步骤
- [x] S1 资源审计：2026-10-19 当前 Ollama `/api/ps` 为空；GPU 总计12227MiB、已用2377MiB，物理内存空闲20460124KiB。不是仍有大模型残留，先前压测可能同时驻留模型。
- [x] S2 策略确定：默认自动安全选择已安装4B，不自动选9B；支持基础模式、Qwen3.5 4B、Gemma3 4B、Qwen3.5 9B。手动选择同样受安全门槛约束。资源未知时基础模式，不盲目转CPU大模型。
- [x] S3 网页与API：选择持久化，显示安装状态/资源建议/当前可用资源；基础推理设备与Ollama视觉大模型设备分开说明。
- [x] S4 生命周期：每次请求前检查资源；单请求串行、4096上下文；本批新加载模型短驻留、完成/取消主动释放；启动前已驻留模型不主动卸载。不卸载用户其他模型。

## 初始保守门槛（项目策略，不是厂商最低配置）
| 模式 | 开始前可用系统内存 | 可用独立显存 | 建议 |
| --- | --- | --- | --- |
| 基础分析 | 大模型不加载 | 不要求独显 | 低配/同时办公；基础识别仍会占用内存，精度和描述能力较弱 |
| 两种4B | ≥8GiB | ≥6GiB | 默认优先Qwen3.5 4B，Gemma为兼容基线；不保证语义更准 |
| Qwen3.5 9B | ≥12GiB | ≥9GiB | 仅主动选择；通常建议32GB内存、12GB或更多独显，需看实际空闲 |

运行中系统空闲低于3GiB或独显空闲低于0.75GiB则保护性停止大模型请求，释放本批拥有的模型；每张前重新判断。模型已驻留时，显存核算考虑其已用显存，不能重复计算加载成本。OOM/超时/资源不足最多一次向4B回退；否则明确转基础分析，不重复冲击内存。不以模型自报置信度当准确率。

## 所有权与限制
启动前已驻留模型不归本批拥有，结束不卸载；仅清理本批从未驻留状态加载的同一模型摘要。Ollama服务是共享的：外部应用若同时接管相同模型，无法从API完全推断所有权，建议筛选期间不要让其他应用使用相同模型。本项目进程内部加互斥，不制造真实OOM测试。当前独显余量探测使用NVIDIA工具；其他厂商/未知显存保守基础模式，不能假装已验证跨硬件大模型加速。NPU目前仅基础路径已验证。

## 精度实验边界
18张同条件样本：Gemma4B热p50约4.11秒、Qwen3.5 4B约2.56秒、9B约3.56秒；三者结构化输出均无失败，但没有独立人工语义/审美真值，不能称9B一定更准。默认选择4B兼顾资源与速度；9B供用户权衡。专用精选模型仍在R4，不混同通用视觉描述模型。
