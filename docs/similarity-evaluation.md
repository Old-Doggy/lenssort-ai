# 相似照片检测评测记录

> 评测日期：2026-10-02
> 评测版本：T3.4 + T3.5  归一化输入 256 × 256、letterbox  0.1

## 评测目的

验证当前本地 dHash + 低频 pHash 组合在常见照片变换和相似外观场景下的边界表现，并为后续 CLIP embedding、旋转不变特征和人工确认策略提供基线。

当前判定规则：

- dHash Hamming 距离不超过 6；
- pHash Hamming 距离不超过 12；
- 两个条件同时满足时加入相似组；
- 不自动删除照片，只生成可解释的人工复核提醒。

## 数据与方法

- 共 20 对、40 张合成评测图片。
- 第一批覆盖：同图复制、JPEG 重编码、亮度变化、裁剪、翻转、旋转、平移、纯色近邻、周期纹理、相似配色场景。
- 第二批覆盖：小角度旋转、180 度旋转、重度/中度裁剪、大幅平移、中心放大、强模糊、强对比度、相似布局不同对象。
- 所有图片先经过 256 × 256 letterbox 归一化，再计算 dHash 和 pHash。
- 实际运行证据：`artifacts/similarity-eval-results.json`、`artifacts/similarity-eval-extra-results.json`。
- 可复现素材：`data/eval/similarity_cases/`、`data/eval/similarity_cases_extra/`。
- 生成与汇总脚本：`tools/generate_similarity_cases.py`、`tools/generate_similarity_cases_extra.py`、`tools/summarize_similarity_eval.py`、`tools/summarize_similarity_extra.py`。

## 错误案例汇总

累计 20 对中 11 个错误：9 个漏判、2 个误报。这里的“预期”是针对评测变换的产品边界标签，不代表真实用户数据集上的最终准确率。

### 漏判

1. 水平翻转：pHash 对方向变化敏感。
2. 90 度旋转：当前特征没有旋转不变性。
3. 轻微平移：边缘补色导致两个哈希同时越过阈值。
4. 5 度旋转：小角度旋转在低分辨率采样后产生较大结构差异。
5. 180 度旋转：整体方向变化改变低频 DCT 分布。
6. 重度中心裁剪：主体保留但全局构图变化过大。
7. 中度中心裁剪：dHash 尚可，但 pHash 超过 12。
8. 大幅平移：补边区域改变整体亮度与边缘关系。
9. 中心放大：主体相同但尺度变化导致 pHash 超阈值。

### 误报

1. 相近配色不同场景：色彩和层级相近，低频结构相似。
2. 相似布局不同对象一：主色、地平线、主体块位置相近，两个哈希均为 0 距离，但语义对象不同。

## 产品边界与后续策略

- 当前 dHash/pHash 适合做低成本候选预筛，不应作为最终语义相似判断。
- 旋转、镜像、裁剪和尺度变化需要加入几何增强或多视图哈希；不在本轮直接放宽阈值，避免扩大误报。
- 误报案例说明纯低频结构不能区分“构图相似”和“对象相同”；T4.7 的 CLIP embedding 应作为二次确认，而不是直接替换 dHash。
- 当前 UI 保留人工确认入口，不自动删除照片；这是在误判率尚未充分验证时的安全产品决策。
- 评测集是合成边界集，后续 T3.6 之外还需要收集真实连拍、旅行照片和不同手机压缩样本。
